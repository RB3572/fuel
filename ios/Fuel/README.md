# Fuel for iOS

The app is the product. It talks to the same Vercel API and Neon database that
[fuel.rishib.com](https://fuel.rishib.com) does, but the web dashboard is legacy and no
longer maintained — everything new lands here.

```bash
cd ios/Fuel && xcodegen generate && open Fuel.xcodeproj
```

SwiftUI, **iOS 26 minimum**, generated by XcodeGen from `project.yml`. Bundle
`com.labloggercompany.fuel`.

> `Fuel.xcodeproj` is generated. Edit `project.yml` and re-run `xcodegen generate`;
> changes made in Xcode's project editor will be erased.

## The five tabs

| Tab | What |
|---|---|
| **Dashboard** | The day: energy balance, nutrition, food log, fitness, workouts, sleep, and every Health metric group. Cards are reorderable; swipe left and right to page between days. |
| **Trends** | Charts over time, dual-axis metric comparison, and Compare — each vital graded against published reference ranges for your age and sex. |
| **Log** | Camera-first. One tap captures, identifies and logs. Album button left of the shutter, chat bubble right. |
| **Coach** | AI chat with a week of persisted history, and a weekly Saturday rundown. |
| **More** | Blood results, body measurements, journeys, places, recipes, lifting, explore, sync settings, notifications, appearance, account. |

The tab bar says **Dashboard**; the page title says **Today**. That distinction is
deliberate.

## What makes it different from the website

- **The AI runs on device.** `FoundationModels` replaces every Gemini call — nutrition
  estimates, photo identification, the coach. No key, no quota, no round trip, and food
  photos never leave the phone. Needs an Apple Intelligence device.
- **You can bring your own key instead.** Claude, OpenAI or Gemini, stored in the
  Keychain, chosen per provider from a three-tier model list in `APIKeyStore.swift`.
  Every AI capability is implemented on both paths.
- **HealthKit is read directly.** No Shortcut, no companion app. The sync engine is
  shared with Health Logger by source path, so there is one implementation — see
  [`HEALTH_SYNC.md`](../../HEALTH_SYNC.md).
- **Widgets.** Sixteen Home Screen widgets plus Lock Screen and Control Center controls,
  in `ios/FuelWidgets`, reading a shared snapshot through the App Group. They never make
  a network call.

## Building and shipping

```bash
# Verify
xcodebuild -project Fuel.xcodeproj -scheme Fuel \
  -destination 'generic/platform=iOS' -configuration Release build

# Ship: bump both CURRENT_PROJECT_VERSION lines in project.yml, then
xcodegen generate
xcodebuild -project Fuel.xcodeproj -scheme Fuel -destination 'generic/platform=iOS' \
  -archivePath /tmp/Fuel45.xcarchive archive -allowProvisioningUpdates
xcodebuild -exportArchive -archivePath /tmp/Fuel45.xcarchive \
  -exportPath /tmp/Fuel45Export \
  -exportOptionsPlist /tmp/FuelExportOptions.plist -allowProvisioningUpdates
```

The build is warning-clean; keep it that way. `HANDOFF.md` §1 has the export options
plist, why the built `CFBundleVersion` is always `1`, and what Apple's daily upload limit
looks like when you hit it.

If you touch anything under `../HealthLogger/Sources/`, build **both** projects — those
files are shared, not copied.

## Sign-in

Google and Apple, both native, matched to an account **by email address** — so signing
in with Apple on the phone and Google on the web lands on the same data, provided the
address matches and you are not using Apple's private relay.

The app posts the provider's ID token to `POST /api/auth/native`, which verifies the
signature against the provider's JWKS and returns a Fuel token pair. See
`api/_lib/native-auth.js`; the verifier is tested against forged, tampered, expired and
downgraded tokens in `test/native-auth.test.js`.

**No secret ships in the bundle.** iOS OAuth clients are public by design; PKCE is what
makes the exchange safe. If no iOS client is configured the app falls back to brokering
through Fuel's own Google flow at `/api/auth/google/start?native=1`, which hands back a
one-time code over `fuel://auth` bound to a PKCE challenge, so an app that hijacked the
scheme cannot redeem it.

The redirect scheme must be the reversed client ID. If the two disagree the sheet opens,
the user signs in, and the callback never arrives — with no error anywhere — so a test
asserts they match.

### Configuration status

| What | Where | State |
|---|---|---|
| App ID with HealthKit + Sign in with Apple | Apple Developer portal | ✅ registered |
| `GOOGLE_IOS_CLIENT_ID` | Vercel env | ✅ set |
| Google iOS client + reversed scheme | `project.yml` | ✅ set |
| App Group `group.com.labloggercompany.fuel` | portal + `project.yml` | ✅ set (widgets) |
| `APPLE_SERVICE_ID` | Vercel env | Sign in with Apple, **web only** |

Sign in with Apple **in the app** needs only the capability, which is registered. The
simulator additionally needs an Apple ID signed in under Settings.

Sign in with Apple **on the web** needs a Services ID: register one (e.g.
`com.labloggercompany.fuel.web`), configure it against `fuel.rishib.com` with return URL
`https://fuel.rishib.com/api/auth/apple/callback`, host the association file Apple gives
you at `public/.well-known/`, then `vercel env add APPLE_SERVICE_ID production`. No
private key is needed — the web flow uses `response_type=code id_token` with
`response_mode=form_post` and verifies the returned `id_token` directly.

## Before you change anything

Read [`HANDOFF.md`](../../HANDOFF.md). In particular:

- §2 — how to **render SwiftUI headlessly** and actually look at visual changes before
  shipping them. This has caught bugs that no amount of re-reading would.
- §6 — the traps: gesture arbitration inside scroll views, `.drawingGroup()` and system
  controls, `.refreshable`, MapKit's limits, HealthKit authorization, Charts axes.
- §4 — the test suite is static source inspection, so refactoring breaks tests **by
  design** and the regexes move with the code.
